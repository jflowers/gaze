unbound-force org content-pipeline convention: blog opportunities for significant changes (new agent, new CLI command, architectural migration, new hero capability) are tracked as dedicated `blog`-labeled issues in unbound-force/website — precedent: #51 (blog: uf init multi-platform scaffolding). Folding a blog opportunity into the Website Documentation Gate's docs issue (a bullet under "pages needing updates") leaves it invisible to the label-filtered blog backlog. Curator reviews should flag a missing blog-labeled issue as MEDIUM even when the docs gate issue verbally acknowledges the topic, and should verify the gate issue itself via `gh issue view` rather than trusting the AGENTS.md Recent Changes claim.
